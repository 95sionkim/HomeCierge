# S-07 저장 보고서

완료된 분석의 **보고서** 탭에서 한 공고·주택형의 결과를 저장한다. 비교 대화에서 “지금까지 내용 보고서로 정리해줘”라고 요청해도 이 탭을 연다. 사용자가 저장을 누르면 보고서 번호와 분석별 버전이 생긴다. 같은 계정으로 다시 로그인해 **내 분석 → 저장 보고서**에서 열거나 PDF를 받을 수 있다. 비로그인 사용자는 합성 예시를 볼 수 있다.

## 저장할 결과를 선택한다

- 보고서는 분석 실행과 원래 수집본을 참조한다. 공고 요약, 주변 실거래 비교, 호실 자금표, 공고일 기준 법령, 지역 뉴스, 출퇴근 경로, 자료 출처와 확인할 항목으로 구성한다. 수집본 저장 시각, 각 출처의 관측 시각, 보고서 저장 시각은 각각의 기록에서 읽는다.
- 비교에 호실이 지정돼 있으면 같은 호실을 사용한다. 주택형만 선택한 분석에서는 자금표에 넣을 호실을 따로 선택할 수 있다. 호실 선택을 생략하면 공고·비교 결과를 저장하고 자금표에 호실 미선택을 표시한다. 공고의 호실별 소계와 자금표의 납부일별 부족액은 각각의 계산 근거를 유지한다.
- 저장 당시의 조건·금액·출처·보류 사유를 사용한다. 공유 프로필 변경, 자금 수정·추가, 새 결과 조회는 기존 보고서에 적용되지 않는다. 원래 자금 항목을 명시적으로 삭제하면 해당 금액을 포함했던 보고서에서도 그 값을 제거하고 남은 자금으로 부족액을 계산한다.
- 실거래 확인 건수와 정상 0건은 저장된 비교 판정을 따른다. 부분 수집·공급면적 미확인은 보류로 표시한다. 같은 날 납부와 자금 유입이 있으면 입금 전·후 부족액을 확정 자금과 예상 자금 포함 기준으로 각각 보여준다.

## 계정으로 보고서를 호출한다

모든 요청은 확인된 비익명 사용자의 JWT를 사용한다. HTTP 응답은 `Cache-Control: private, no-store`를 사용한다.

| 요청을 보낸다 | 응답을 처리한다 |
| --- | --- |
| `POST /api/v1/analyses/{analysisId}/runs/{runId}/reports` | JSON `{requestId, fundingRoom?}`. `requestId`는 UUID이고 `fundingRoom`은 원 수집본에 대응하는 호실 이름이다. 201과 `Location`, 저장된 본문을 반환한다. 응답을 받지 못했을 때 같은 키·같은 실행·같은 호실로 재시도하면 기존 버전을 받는다. 새 버전은 새 키로 저장한다. |
| `GET /api/v1/reports?before={reportId}` | 본인의 최근 보고서부터 최대 30건과 `nextCursor`를 반환한다. 첫 요청에서는 `before`를 생략한다. 출처 표시가 제한된 보고서는 목록에서도 공고명을 가린다. |
| `GET /api/v1/reports/{reportId}` | `saved-report/v1`. 각 항목에는 확인 상태, PDF 포함 권한, 근거 행, 표와 보류 설명이 있다. |
| `GET /api/v1/reports/{reportId}/pdf` | 내보내기 시점에 권한을 다시 확인해 PDF를 생성한다. 요청자에게 첨부 파일로 전송한다. |
| `DELETE /api/v1/reports/{reportId}` | 삭제 확인 후 해당 보고서 한 건을 제거하고 204를 반환한다. 목록·본문·PDF에서 사라지며, 삭제한 저장 요청을 재전송하면 409다. 원래 분석과 대화는 계속 열 수 있다. |

형식 오류는 400, 미인증은 401, 타인·누락·삭제된 보고서 조회는 404다. 아직 비교 결과가 없는 실행이나 재사용할 수 없는 저장 키는 409다. 저장 요청은 화면이 만든 금액·표·사용자 ID를 입력받지 않는다.

## PDF에 포함할 자료를 확인한다

실수집 자료는 해당 출처의 저장·재사용·표시와 보관기간을 확인한다. 현재 권한이 제한된 항목은 보류로 표시하고 이용 가능한 항목은 계속 제공한다. PDF에는 별도 내보내기 허용이 있는 값만 포함한다. 화면과 PDF는 같은 보고서의 계산·표시 자료를 사용한다. 한글 글꼴을 파일에 포함하며 로그인 세션으로 매번 내려받는다. 원본 첨부 PDF를 복사하거나 공개 다운로드 주소를 만들지 않는다.

뉴스와 경로에는 원래 분석에서 다시 조회할 수 있는 기능을 안내한다. 기사·발췌문, 출퇴근 목적지, 좌표와 실시간 경로는 저장 보고서와 PDF에 복제하지 않는다. 관련 요구는 R-11·R-12, 수락 기준은 A-44·A-58이다. [제품 요구](../prd/01-product-prd.md) · [자금표](funding-plan.md) · [지역 뉴스](regional-news.md)

## 검수 기록

2026-11-23 서울 개발 Supabase에 로그인한 임시 계정 두 개와 합성 공고·납부 일정으로 검수했다. 같은 요청을 동시에 저장해 보고서 하나를 받았고, 다른 계정에서 본문·PDF·삭제를 요청했을 때 각각 404를 받았다. 소유자의 새 브라우저 세션에서 공유 예산을 변경한 뒤 기존 보고서를 열어 저장 내용과 한글 PDF 다운로드를 확인했다. 합성 계약금 납부일에 예상 자금을 포함한 부족액은 입금 전 2,100만 원, 입금 후 1,600만 원이었다. 삭제 후 같은 요청 재전송은 409였고 원래 분석을 다시 열 수 있었다. 상시 작업자가 동작하는 개발 환경에서 이 검사만 실행하려면 개발 인증 환경을 연결하고 `npm run test:auth -- --saved-reports`를 실행한다.
