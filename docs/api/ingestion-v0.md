# 공고·실거래 수집과 정규화 (BE-02)

한 공고의 기본 정보·주택형과 지역·계약월별 실거래를 읽어 저장 단계에 넘길 수 있는 JSON을 만든다. 청약홈 신규분양·잔여세대 계열의 공고와 주택형, 국토교통부 아파트 매매·분양권전매가 대상이다. 재생 CLI는 파일의 합성 응답만 읽으며 계정이나 API 키가 필요 없다.

## 한 공고의 수집을 재생한다

저장소 루트에서 실행하면 표준 출력에 `ingestion/v0` 결과가 나온다. 두 번째 명령은 Python이 만든 실거래 수집 기록을 화면팀의 BE-01 스키마로 검사한다. Node.js 26과 `npm ci`로 설치한 개발 의존성이 필요하다.

```sh
python3 scripts/replay_ingestion.py tests/fixtures/ingestion-v0.json
npm run test:ingestion
```

[재생 파일](../../tests/fixtures/ingestion-v0.json)의 `request`에는 청약홈 출처, 주택관리번호·공고번호, 문서 대조 회차, 기준일, 요청 지역 코드, 거래 종류가 있다. `pages`는 출처·요청 조건·페이지 번호·페이지 크기와 조회 시각으로 식별한다. `evidence`에는 원문 대조를 마친 값이나 아직 확인할 문서 항목을 전달한다. 날짜 범위를 지정하면 양 끝을 포함한 사용자 확인 기간으로 처리한다.

## 공고와 거래를 읽는 순서

1. 주택관리번호와 공고번호로 공고를 조회하고, 같은 두 번호로 그 출처의 주택형을 조회한다. 필터 조회에서는 일치하는 건수와 받은 행을 대조한다.
2. 호실 가격에 쓰는 근거를 공고·회차·주택형·호실과 연결한다. API가 제공하는 주택형별 최고금액은 별도로 기록한다. 호실 분양가와 그 호실에 적용되는 필수 옵션을 확인해야 구매가격 소계를 계산한다. 세금·금융비용은 이 소계에서 제외한다.
3. 거래 기간이 걸치는 모든 계약월에 대해 요청 지역별로 필요한 출처를 조회한다. 매매는 `apt_trade`, 분양권·입주권은 하나의 `apt_rights` 요청을 공유한다. 기준일이 2026-11-10이면 기본 범위는 2025-11-11부터 2026-11-10까지다. 13개 계약월을 읽고 개별 거래는 정확한 계약일로 구분한다.
4. 수집 기록과 거래행을 따로 남긴다. 매매·분양권·입주권, 해제 여부, 기간 밖 거래, 면적과 식별 근거를 보존한다. API의 요청 지역 코드(`LAWD_CD`)와 거래의 전용면적만으로 제품의 우선 지역이나 공급면적 대응을 확정할 수 없다.

## 결과를 읽는다

| 결과 필드 | 다음 단계에서 사용할 내용 |
| --- | --- |
| `target`, `asOf`, `period` | 공고와 문서 대조 회차, 조회 기준일, 적용 기간과 요청 계약월. 미정 경계는 사유와 함께 보류한다. |
| `catalogCollections` | 공고와 주택형 각각의 출처, 요청 조건, 수집 상태와 건수 |
| `catalog` | 공고·주택형 관측값, 호실별 확인된 가격과 문서 근거, 보류 또는 충돌 사유 |
| `tradeBatches[].record` | 출처·지역·월 단위의 BE-01 `collectionRecord`. `complete`는 필요한 페이지와 행을 확인한 상태, `empty`는 해당 요청에서 확인한 정상 0행이다. `partial`은 부분 수집, `failed`는 사용 가능한 페이지를 확보하지 못한 상태다. |
| `tradeBatches[].reasons`, `trades` | 상태의 사유와 실제로 확보한 거래행. 페이지가 누락되면 먼저 확보한 행을 유지한다. |

같은 거래처럼 보이는 두 행도 출처의 페이지와 행 위치를 남긴다. 안정적인 거래 식별자가 없는 상태에서 관측된 행을 임의로 합치지 않는다. 수집 기록의 식별자는 이번 결과 안에서 요청 범위를 연결하는 데 쓴다. 새로 조회한 관측값의 저장 버전과 재적재는 BE-03에서 다룬다.

페이지 수가 원래 보고된 건수로 계산되지 않거나, 같은 페이지가 반복되거나, 보고 건수가 바뀌면 수집 사유를 남긴다. 한 요청에서 10,000쪽을 넘는 계획은 작성하지 않는다. 이는 외부 응답 하나가 만드는 조회·누락 목록의 기술 한도다. 운영 쿼터와 재시도 일정은 별도로 정한다. 실전송을 연결하는 호출자는 `ingest`에 기존 조회 도구를 사용하는 `LiveProbeTransport`를 명시적으로 전달한다. CLI와 기본 검사는 `ReplayTransport`만 사용한다.

내용과 순서가 통째로 같은 두 페이지는 별개 거래 묶음일 수도 있다. 현재 수집기는 행을 모두 남기고 `repeated_page`로 완전성 판정을 보류한다. 실서비스가 빈 계약월을 별도 업무 코드로 반환하는지는 실자료 검증 과제다. 확인된 성공 응답과 0건 근거를 갖춘 경우에만 `empty`로 분류한다.

### 합성 공고에서 금액과 보류 사유를 확인한다

예시에서 청약홈이 보고한 공급면적은 112.40㎡이고 같은 주택형의 합성 문서 4쪽에서 확인한 값은 112.400㎡다. `housingTypes[].supplyArea`는 API 보고값을, `checkedSupplyArea`는 문서 대조 결과를 제공한다. 주택형 최고금액은 7억 5천만 원이며, 아래 호실 금액은 같은 공고·회차·주택형에 연결한 문서 7~8쪽에서 나온다. JSON에서는 금액을 원 단위 십진 문자열로 전달한다.

| 호실을 조회한다 | 분양가를 확인한다 | 필수 옵션을 확인한다 | 예산과 비교할 소계를 확인한다 |
| --- | --- | --- | --- |
| 101동 101호 | 7억 원 | 1천만 원 | 7억 1천만 원 (`confirmed`) |
| 101동 102호 | 7억 2천만 원 | 미확인 | `null` (`held`) |

문서 근거 한 건은 `document`의 식별자·버전·출처(`official` 또는 `upload`)·공고 번호쌍·회차, PDF의 `page`, `modelNo`·`houseType`, 항목(`item`)과 점검 상태(`check`)를 연결한다. 주택형 공급면적에는 `basis: "supply"`, `unit: "m2"`, `m2`가 필요하다. 호실 금액에는 `room`·`won`을 사용한다. 필수 옵션이 없다고 확인한 경우에만 `required_options`에 `confirmed`와 `"0"`을 함께 쓴다. 소비자는 `rooms[].subtotal`의 상태와 `housingTypes[].subtotalRange`의 확인·보류 호실 수를 함께 읽는다.

`document.source`는 확보 경로다. 공식 경로에서 확인한 원본은 `official`로 입력한다. 사용자 업로드는 공식 원본과 출처를 대조한 결과를 `document.originCheck`에 기록한다. `confirmed`인 업로드는 공고·회차·페이지·항목 점검을 거쳐 사용할 수 있다. 출처 확인이 보류된 문서에서 같은 공고·회차·주택형에 속한 호실을 식별하면, 그 호실은 독립적으로 확인한 금액이 생길 때까지 사유와 함께 보류 건수에 포함한다.

매매 3행 가운데 10월 20일 계약은 5억 1,500만 원으로 정규화되어 지역·단지·공급면적의 후속 확인 대상으로 남는다. 10월 21일 계약은 해제 근거로, 10월 9일 계약은 요청 시작일(10월 10일) 전 거래로 각각 제외된다. 권리 거래 2행에서는 분양권과 입주권이 한 건씩 관측된다.

## 화면과 저장 단계에 인계한다

화면팀은 [분석 결과 계약](analysis-result-v0.md)의 정상 0개·부분 수집·출처 오류 예시를 계속 사용할 수 있다. BE-02가 실제로 생성하는 것은 그 계약 중 수집 기록과 비교 전 입력이다. 같은 동의 비교 후보가 0개인지 판단하려면 후속 비교 엔진에서 지역·단지·공급면적의 대응 근거까지 확인해야 한다.

BE-03 작업자는 이 결과와 조회 요청을 같은 분석 스냅샷에 저장한다. 같은 수집 키로 다시 보내면 최초 결과를 읽을 수 있다. [저장 명령과 근거 조회](ingestion-storage.md)

실자료 조회에는 출처별 이용 조건을 적용한다. BE-06 문서 작업자는 공고·주택형을 조회한 직후 공식 첨부를 읽고 이 계약에 맞는 값별 근거를 만든다. 다른 서식의 추출 정확도와 실거래 후보의 공급면적 대응률은 각각 추가 검수가 필요하다. [공고 문서 작업자](notice-documents.md) · [출처별 이용 조건](be-01-evidence.md) · [대표 단지 검산](be-05-real-case.md)
