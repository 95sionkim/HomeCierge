# BE-05 대표 실자료 공급면적 대응 검증

2026-11-21(한국시간) · V1 단일 단지 검증 · M2 수작업 대조의 일부

**강변역 센트럴 아이파크의 권리 거래 5행 중 해제 1행을 제외했다.** 유효 4행은 전용면적을 정확히 대조했을 때 최초 공고상 주택형 후보가 각각 1개였다. 거래에 적용할 공급면적은 **확인 0행, 불일치 0행, 보류 4행**이다. 84C는 공식 공고 간 공급면적이 달랐고, 84A·84B는 최초 공고의 값이 해당 계약 시점에도 적용된다는 근거가 부족했다.

## 1. 자료 이용 범위와 단지를 확인한다

- 원자료 열람에 앞서 두 국토교통부 API 카탈로그의 무료·이용허락범위 제한 없음 표기, 포털 약관 제14조와 제3자 권리 조건을 확인했다. 2026-11-09에 원 프로젝트가 수집한 응답을 해당 프로젝트에서 읽기 전용으로 검산했다. 신규 인증 API 호출과 키 사용은 0회다. [매매 상세 API](https://www.data.go.kr/data/15126468/openapi.do) · [분양권전매 API](https://www.data.go.kr/data/15126471/openapi.do) · [이용 조건 조사 기록 BE-01 §5](be-01-evidence.md)
- 사업주체의 공고는 공식 공개본을 열람하고 기존 보관본은 보관 당시의 출처 기록과 해시를 점검했다. 한국부동산원의 자유이용 정책은 한국부동산원이 저작재산권 전부를 보유한 자료에 적용된다. 여기에는 공개 공고의 식별·면적 근거와 거래 집계만 기록했다. 제품 저장·재사용·외부 제공 조건은 D-07 확인 사항이다. [데이터 취급 원칙](../data-handling.md) · [수집 결과 저장 계약 §4](ingestion-storage.md)
- 대상은 **서울특별시 광진구 구의동 592-39번지 일원의 강변역 센트럴 아이파크**다. 최초 공고 2024000226과 두 재공급 공고가 같은 단지명·공급 위치를 가리킨다. 기존 광진구 거래 스냅샷과 같은 단지의 공식 공고를 함께 검산할 수 있어 이 사례를 선정했다. 9월 공고는 청약홈 보관 응답의 주택관리번호·공고번호 2026930040, 공고일, 단지명, 지번을 PDF와 대조했다. [기존 공고 검수 기록](pdf-supplement-validation.md)

## 4. 거래별 판정과 한계를 기록한다

| 검토한 결과를 구분한다 | 행을 센다 | 근거를 적는다 |

| 공급면적 대응 확인 | 0 | 거래별 적용값의 근거가 확인된 행이 없다. |
| 공급면적 대응 불일치 | 0 | 거래 쪽에서 독립적으로 확인된 공급면적이 없어 행 단위 불일치를 판정할 수 없었다. 공고 간 수치 차이는 아래 보류 사유에 포함했다. |

## 5. 같은 모집단을 재검산한다

다음 상대 경로는 HomeCierge와 별개인 `0.LLM-Agent` 원 프로젝트 기준이다. 저장본 접근 권한이 있는 검토자가 로컬에서 집계만 재생할 수 있다.

| 저장본을 고른다 | XML 페이지 묶음의 SHA-256을 대조한다 |
| --- | --- |
| `api-evidence/20261109T062200941669Z_recent_apt_trade/` | `a3c7d69b4302e0116b52d8b06bcbdc863261d3f3445e62a5d0e6e591690ffc87` |
| `api-evidence/20261109T062233150979Z_recent_apt_rights/` | `ce837079ab7b8a528877b212b63eba993ec0911d6854f96b76fa86513de146a2` |

1. 위 각 폴더의 `summary.json`에서 시군구와 12개 계약월을 확인한다. 계약월·페이지 오름차순으로 `page_*_response.xml`의 개별 SHA-256을 구한다. 64자 소문자 16진 다이제스트를 구분 문자 없이 이어 붙인 ASCII 바이트에 SHA-256을 적용하면 표의 묶음 값이 나온다.
2. XML의 `response/body/items/item`을 월별 `coverage.json`·`normalized.json`과 대조한다. 기존 수집기의 `assess_month`와 `normalize`는 로컬 입력으로 재사용할 수 있다. §2의 계약일·단지 필터를 계약월·페이지·행 순서에 적용하고, 해제 제외 후 §3의 전용면적을 `Decimal`로 대조한다. [기존 거래 수집기](../../scripts/collect_recent_trades.py)
3. `pdf-evidence/2026930019/`와 `pdf-evidence/2026930040/`의 `notice.pdf` SHA-256을 각 `source.json`과 비교한다. 9월 청약홈 대조는 `api-evidence/20261106_live/case_detail/`과 `case_model/`의 응답을 사용한다. 최초 공고 5·6쪽은 §3의 공식 링크에서 확인한다. 새 조회 시점에는 추가 신고·정정·해제로 집계가 달라질 수 있으므로 위 저장본과 구별한다.

### 실제 비교 엔진에서 판정을 대조한다

같은 XML 24페이지의 광진구 매매·분양권·입주권 963행을 메모리에서 BE-02 `ingest`로 정규화하고 `compare_snapshot`에 전달했다. 출처별 원래 페이지 크기와 실거래 수집 기록의 시각을 사용했다. 청약홈은 브라우저 보관본의 공고·주택형 본문과 파일 저장 시각을 사용했으며, 당시 HTTP 상태는 미기록이다. 9월 공고 PDF 4쪽과 일치한 84C의 공급면적 105.8939㎡를 분석 기준으로 사용했다. 대상 유효 4행에는 §2에서 확인한 단지 연결만 입력했고, 개별 거래의 공급면적 대응값은 비워 두었다. 다른 행의 법정동 소속은 공개 코드표와 실거래의 위치 필드로 대조했다.

| 구의동 우선 범위에서 처리한 관측 | 엔진에서 확인한 결과 |
| --- | --- |
| 대상 유효 4행 | 주변 집계에서 자체 거래로 분리(`target_complex_trade`)했다. 4행 모두 자체 거래로 표시된 공급면적 보류(`trade_supply_area_unverified`, `targetReference=true`)였다. 확정 자체 거래(`targetReferences`)는 0건이다. |
| 대상 해제 1행 | `cancelled_trade`로 제외됐다. 보류 4행에는 포함되지 않으며, 대상 거래 여부는 메모리에서 원자료의 관측 위치로 대조했다. |

엔진은 **구의동 우선 범위 유지, 광진구 확대 없음**으로 반환했다. 수집은 완료였고 후보 판정은 보류(`held`), 전체 결과는 부분(`partial`)이었다. 확정 주변 후보와 표시된 비교 단지는 모두 0개다. 자체 거래의 확인 0/4와 별도로, 다른 거래 319행의 단지 연결이 남아 있어 구의동의 주변 정상 0개는 확정되지 않았다.

**M2에서 확인한 범위는 한 단지의 권리 거래에 대해 수작업 판정과 엔진의 보류·해제 처리가 일치한 데까지다.** 공급면적이 확인되는 비교 사례에는 계약일에 적용되는 공식 공급면적과 비식별 주택형 연결 근거가 필요하다. 전용면적에 대응하는 가능한 모든 호·주택형에 같은 공급면적이 적용됐다는 공식 근거로도 판정할 수 있다. 그 근거를 확보한 뒤 ±5% 범위 판정과 가격 통계를 대조한다.
