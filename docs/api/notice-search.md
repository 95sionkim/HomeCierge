# 로그인 사용자의 공고 탐색

화면의 지역 선택기는 `GET /api/v1/notices/regions`로 목록 전용 게시본의 공식 지역과 명칭을 읽는다. 응답은 `notice-regions/v1`, `dataOrigin`, `observedAt`, `regions[{code,name}]`를 포함한다. 해당 기간 공고가 없는 지역도 선택할 수 있고, 공식 명칭이 없으면 코드를 표시한다. 개인 검색은 기존 `POST /api/v1/notices/search`의 별도 게시본에서 판정한다.

2026-11-22 서울 개발 환경에서 논산시·예산 10억 원으로 검색하니 공식 지역 269개 중 논산을 선택할 수 있었고, 당시 색인의 198개 공고 중 조건 충족 0개·확인 필요 2개·제외 196개였다. 호실 가격 근거가 부족해 0건 판정은 `indeterminate`였다.

`POST /api/v1/notices/search`는 희망 지역과 구매 가격 상한을 받아 청약홈 공고를 찾는다. 사용자가 이전에 분석한 공고가 없어도 탐색할 수 있다. 화면은 `matched`(조건 충족)와 `needsReview`(확인 필요)를 함께 표시한다. [제품 요구 R-15](../prd/01-product-prd.md)

## 화면에서 조건을 보낸다

Supabase 사용자 access token을 `Authorization: Bearer <access_token>`에 넣고 `Content-Type: application/json`으로 전송한다. 아래 금액과 조건은 합성 예시다.

```json
{
  "regionCodes": ["11215", "11200"],
  "budgetMaxWon": "1300000000",
  "supplyArea": {"min": "100", "max": "110", "unit": "m2"},
  "moveIn": {"start": "2027-01", "end": "2028-03"},
  "includeClosed": false
}
```

- `regionCodes`와 `budgetMaxWon`은 필수다. 지역은 복수 시·군·구의 5자리 코드, 예산은 사용자가 정한 구매 가격 상한을 원 단위 정수 문자열로 전달한다. 코드의 상위 행정구역과 이름은 행정표준코드관리시스템의 현존 자료로 확인한다. [법정동코드 전체자료](https://www.code.go.kr/stdcode/regCodeL.do)
- `supplyArea`는 공급면적의 양끝을 포함한다. 단위는 `m2` 또는 `pyeong`이며 표시용 반올림을 필터 판정에 쓰지 않는다. `moveIn`은 양끝 월을 포함하는 희망 구간이다. 공식 입주 예정 구간과 한 달이라도 겹치면 충족한다. 이 두 조건을 생략할 수 있다.
- 기본 목록은 접수 중 공고를 마감일순, 예정 공고를 시작일순으로 표시한다. `includeClosed: true`로 종료 공고를 포함한다. 판정 기준일은 요청을 받은 시점의 한국 날짜다. 접수 구간이 나뉜 공고는 공식 전체 기간과 확인된 세부 기간을 함께 사용한다. 세부 기간 사이의 날은 접수 중으로 추정하지 않는다. 공고의 접수 상태와 개인의 청약 자격은 별도다.
- 검색 요청의 조건은 해당 조회에만 적용된다. 프로필에 반영하려면 사용자에게 변경 내용을 확인받고 기존 승인 경로를 호출한다. [프로필 변경 승인](../frontend-handoff.md)

## 응답을 표시한다

| 필드를 읽는다 | 화면에서 의미를 전달한다 |
| --- | --- |
| `asOf`, `observedAt`, `publicationWindow`, `coverage` | 접수를 판정한 한국 날짜, 목록을 수집한 시각, **모집공고일 기준** 수집 구간과 두 출처의 수집 상태를 표시한다. 접수 기간이 길어서 구간 시작보다 먼저 게시된 공고는 이 색인에 없을 수 있다. |
| `matched[].models[].matchedRooms` | 동일 주택형·호실에서 모든 조건을 만족한 근거를 표시한다. 예산 비교 금액 `subtotalWon`은 분양가와 필수 옵션 합계다. 세금·금융비용은 별도다. |
| `needsReview[]`, `reasonCodes`, `needsReviewRooms` | 확인된 충족 호실이 없고 일부 정보가 비어 있으면 사유와 함께 남긴다. 충족 공고 안에도 다른 미확인 호실이 있을 수 있다. |
| `areaEvidence`, `priceEvidence` | 확인값이 적용된 공식 문서·판본·페이지를 보여 준다. API 최고금액을 호실 소계로 쓰거나 미확인 옵션을 0원으로 채우지 않는다. |
| `counts`, `truncation`, `zeroStatus` | 판정 대상 전체의 건수와 응답에서 생략한 항목을 구분한다. 선택 코드가 공식 현존 목록에 없으면 `scopeIssues`에 `region_selection_unverified`를 남긴다. 확인 필요 항목이 있거나 관측일·수집 구간·출처가 불완전하면 정상 0건으로 표시하지 않는다. `confirmed_zero`의 범위는 응답에 명시한 공고일 구간과 출처다. |

예산이 7억 1천만 원이고 한 호실의 분양가가 7억 원, 확인된 필수 옵션이 1천만 원이면 경계값을 포함한다. 같은 주택형의 다른 호실에서 옵션 금액이 비어 있으면 그 호실은 확인 필요다. 예산을 1원 낮췄을 때 두 번째 호실의 금액이 여전히 미확인이면 공고는 확인 필요 목록에 남는다.

| HTTP 응답을 확인한다 | 화면에서 처리한다 |
| --- | --- |
| 200 | 두 목록과 수집 범위·시점을 함께 표시한다. |
| 400 `invalid_search_input`, 413, 415 | 입력 형식이나 요청 크기(최대 4 KiB), JSON 본문 유형을 확인한다. |
| 401 `authentication_required` | 로그인 세션을 확인한다. |
| 403 `search_source_restricted` | 검색 자료의 표시 권한을 확인하고 있다는 안내를 제공한다. |
| 503 `search_index_not_ready` | 게시된 최신 색인이 준비되지 않았다. 정상 0건을 표시하지 않는다. |
| 503 `backend_unavailable` | 저장소 연결이나 결과 형식 검사에 실패했다. 잠시 후 다시 시도한다. |

## 서버에서 목록을 준비한다

작업자가 정한 공고일 범위로 청약홈 APT 및 무순위·잔여세대 목록의 모든 응답 페이지를 확인한다. 출처마다 완료·정상 빈 응답·부분·실패를 구분한다. 소재지 주소는 현존 법정동코드 자료로 시·군·구에 대응한다. 공고 유형은 해당 조회의 공식 코드·명칭으로 확인한다. 별도 임의공급 조회의 포함 여부와 유형을 식별하지 못한 서식은 D-04의 추가 검수 대상이다. 주택형별 공식 면적과 호실 소계는 정해진 전처리 건수 안에서 같은 공고의 주택형 API와 공식 첨부를 읽어 점검한다. 두 목록 API의 구조화 자료와 제3자 공고문에는 출처별 이용 조건이 각각 적용된다. [청약홈 분양정보 서비스 명세 및 이용허락범위](https://www.data.go.kr/data/15098547/openapi.do) · [공식 첨부 점검 절차](notice-documents.md)

작업자 전용 `publish_notice_search_index`는 정규화한 공고 전체를 한 번에 게시한다. 같은 관측의 재시도는 같은 내용일 때만 허용하며 이전 관측으로 최신 색인을 덮어쓰지 않는다. 로그인 요청은 사용자 JWT로 `read_notice_search_index`를 호출한다. 두 공고 목록과 현존 지역코드, 실제 사용한 주택형·PDF 출처의 보관·재사용·표시 권한을 다시 대조한다. 사용자 업로드·계정별 분석·예산 조건은 공유 색인에 싣지 않는다. 새 색인은 서버에서 게시하므로 검색 버튼을 누를 때마다 공공 API나 PDF를 다시 요청하지 않는다.

### 개발 색인을 갱신한다

행정표준코드관리시스템에서 ‘법정동 코드 전체자료’를 내려받고 압축을 푼 TXT를 작업자에게 전달한다. 작업자의 실행 환경에서 `DATA_GO_KR_SERVICE_KEY`를 사용한다. 아래는 2026년 11월 22일 검수에 사용한 공고일 구간이다. 실제 게시할 때는 종료일을 관측한 한국 날짜로 갱신한다.

```sh
python3 scripts/build_notice_search_index.py --live \
  --start 2026-10-22 --end 2026-11-22 --region-codes /path/to/regions.txt \
  --max-detail-notices 0 --max-document-requests 0
```

서울 개발 DB에 게시할 때는 작업자 전용 환경에 `SUPABASE_URL`·`SUPABASE_WORKER_KEY`를 설정하고 같은 명령에 `--publish`를 추가한다. 위 예시는 두 구조화 목록만 수집한다. 공식 PDF와 모델 데이터가 필요한 선처리는 사용한 출처 모두의 이용 조건이 등록된 환경에서 진행한다. 개발 색인의 공고일 수집 구간 상한은 366일이고, 관측 시점으로부터 72시간까지 조회할 수 있다. 최신 관측이 만료되면 작업자가 새 색인을 게시해야 한다. 이번 개발은 수동 갱신을 지원한다. [법정동코드 제공기관과 이용허락범위](https://www.data.go.kr/data/15077871/openapi.do) · [작업자 실행 파일](../../scripts/build_notice_search_index.py)

### 실제 자료의 예산 경계를 검수한다

2026년 9월 23일 모집공고일로 한정해 두 목록을 실제 조회했다. APT는 정상 빈 응답, 무순위·잔여세대는 공고 4건이었다. 네 공고의 주택형과 공식 첨부를 읽고 11월 22일 기준으로 종료 공고를 포함해 판정했다. 광진구, 공급면적 105.8939㎡, 입주 예정 2026년 11월, 상한 1,243,800,000원에서 강변역 센트럴 아이파크 101동 402호가 충족했다. 이 호실의 소계는 4·5쪽 근거에 연결됐다. 상한을 1원 내리면 해당 호실과 공고가 제외됐다. 이 과거 하루의 결과를 현재 공급 전체의 정상 0건으로 표시하지 않는다. [공식 공고와 호실 가격 대조](notice-documents.md)

2026년 11월 22일 13:42 한국 시각에 개발 DB에는 10월 22일~11월 22일의 두 구조화 목록만 게시했다. APT 45건·무순위/잔여세대 38건, 총 83개 공고와 공식 지역코드 269개다. 공고 80건은 시·군·구까지 확인했고, 나머지 3건은 소재지 근거가 부족했다. 광진구와 성동구·13억 원·종료 제외 조건에서는 충족 0건과 확인 필요 1건이었다. 그 한 건은 소재 시·군·구도 미확인이며 두 지역의 확정 공고 수에 넣지 않는다. 이 개발 색인에는 호실별 가격을 게시하지 않았다. 위 9월 사례의 예산 양성 검수는 실제 공고와 공식 첨부를 메모리에서 결합해 별도로 수행했다.
