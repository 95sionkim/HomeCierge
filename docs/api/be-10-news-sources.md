# BE-10 지역 뉴스 출처와 이용 범위

2026-11-22 공개 문서 확인. **등록한 애플리케이션에서 NAVER 검색결과를 그대로 즉시 표시하는 데 적용할 약관 근거를 확인했다.** 운영 Application 등록 상태, 수익화 방식, 실제 화면의 출처 표시는 별도로 확인해야 한다. PRD는 제목·검색 발췌·원문 링크·게시시각·검색 조건과 지역 관련성 미확인 상태를 함께 제공하도록 요구한다. [R-10·A-14](../prd/01-product-prd.md#12-수용-기준)

## 적용 상품을 확인한다

공개 검증 설정의 `news_search`는 네이버 클라우드 플랫폼(NCP) **NAVER API HUB**의 `GET https://naverapihub.apigw.ntruss.com/search/v1/news`를 사용한다. 2026-06-25 API HUB 출시, 2026-07-31 개발자센터 신규 신청 종료, 2027-06-30 기존 신청 지원 종료가 공지됐다. 이전 개발자센터의 `openapi.naver.com` 서비스와 인증키는 구분한다. API HUB의 계약 근거는 2026-10-07 시행 **NAVER API HUB 서비스 이용약관**이다. 일반조건 1·2는 NCP를 통한 제공과 이용자 웹사이트를 명시하고, 검색 특약이 일반조건보다 우선한다. [공개 검증 설정](probes.json) · [개발자센터 이관 공지][migration] · [현행 API HUB 이용약관][terms]

## 행위별 이용 범위를 확인한다

| 이용하려는 행위 | 약관에서 확인한 범위와 HomeCierge 적용 |
| --- | --- |
| 요청 직후 검색결과를 표시한다 | 검색 특약 1.1·1.2는 앱에서 NAVER 검색결과를 보여 주는 목적의 사용을 허용한다. 다른 결과나 본문과 섞지 않고 독립된 영역으로 노출한다. 제공된 결과의 순서와 내용을 보존하고 자체 재정렬·중복 제거·요약·축약·다른 내용 삽입을 하지 않는다. 제공자의 정렬과 페이지 크기는 검색 요청 조건으로 정한다. |
| 출처를 표시하고 원문으로 연결한다 | 검색결과 전체에 NAVER 검색임을 상표·브랜드 아이덴티티(BI) 가이드에 맞춰 표시한다. 기사별 원본 출처와 원문 이동 링크를 제공한다. `originallink`는 기사 원문 URL이며 `link`는 네이버 뉴스 URL 또는 미제공 기사의 원문 URL이다. 뉴스 명세에 언론사명 필드는 없다. 원문 URL의 호스트를 표시할 경우 확인한 원문 도메인으로 명시한다. 로고를 사용하는 경우 BI 가이드는 API HUB 포털로 연결하도록 안내하고 텍스트 적용 방식도 안내한다. [API HUB 상표·BI 사용][brand] · [뉴스 검색 명세][search] |
| 캐시를 사용한다 | 검색 특약 1.3·1.4는 원자료·가공물·파생물의 복사·저장·캐시를 제한한다. 서비스 연속성에 필요한 범위에서 기기 장애 대응·개인화에는 **최대 24시간 또는 새 질의까지 중 더 짧은 기간**, 서버 이력 열람에는 **최대 21일**, 서버 개인화에는 **기기와 같은 기간**의 임시 보관이 예외다. 기간 만료 뒤 지체 없이 삭제해야 한다. 이 예외를 제품 저장 설계나 일반적인 데이터 재사용의 허락으로 확대할 근거는 없다. |
| 장기 보고서·대화·PDF에서 재사용한다 | 장기 보관과 제3자 제공·판매는 기본 허용 범위에서 벗어난다. 21일 예외는 이력 조회 목적의 임시 보관이며 보고서 스냅샷이나 배포용 PDF의 근거로 쓰지 않는다. 동일 사용자 PDF 다운로드도 공개 약관에서 별도 허용을 확인하지 못했다. 제목·발췌·원문 URL 등 검색 결과를 영속 저장·공유·내보내기 하려면 제공자의 서면 조건 및 해당 권리 범위를 확인한다. |
| 기사 전문을 확보하거나 AI에 입력한다 | `description`은 제공된 검색 발췌다. API가 준 링크로 기사를 읽을 수 있으나 기사 전문을 수집·복제하는 권한까지 부여하는 조항은 확인되지 않았다. 검색 특약 1.3은 결과의 AI 입력, 학습·개선·평가·노출에 활용하는 행위를 금지한다. 검색 결과를 대형 언어 모델(LLM)의 요약·프롬프트·검색 증강 생성 입력으로 사용하려면 별도 권한이 필요하다. 결과 데이터의 권리는 네이버나 원저작자 등에게 남는다(일반조건 8.1·8.2). |
| 운영 환경에서 공개한다 | 검색 특약 1.3은 결과 페이지 광고와 검색 API를 활용한 수익을 금지한다. 일반조건 7.2③은 사용자로부터 API 사용의 대가를 받는 행위를, 7.3⑥은 API 자체를 제3자에게 다시 제공하는 행위를 제한한다. 등록된 앱의 사용자 화면 안에서만 표시하는 범위로 검토하며, 적용 계정·Application·결과 페이지의 실제 운영 방식을 확인한다. |

특약 번호는 2026-10-07 시행본의 `나. 개별 API 별 특약조건 – 네이버 검색 API 서비스`를 기준으로 적었다. [현행 API HUB 이용약관][terms]

## 요청 조건과 시간의 의미를 확인한다

- **접근.** NCP 콘솔의 API HUB 이용 신청·약관 동의·Application 등록과 NAVER 검색 뉴스 선택이 필요하다. 발급한 Client ID와 Client Secret은 서버 요청의 `X-NCP-APIGW-API-KEY-ID`, `X-NCP-APIGW-API-KEY` 헤더로 보낸다. [뉴스 검색 명세][search] · [API HUB 사용 가이드][guide]
- **조회.** `query`는 UTF-8, `display`는 1~100, `start`는 1~1000이다. `sort=date`는 날짜 내림차순, `sort=sim`은 정확도 내림차순이며 JSON과 XML을 제공한다. 요청에 쓴 검색어·정렬·요청 건수와 API 조회 시간을 기사 묶음 밖에 표시한다. 검색어에 지역명이 있어도 관련성은 미확인이다. [뉴스 검색 명세][search]
- **제목·발췌·시각.** `title`은 제목, `description`은 **NAVER 검색 발췌**, `pubDate`는 네이버에 제공된 시각(미제공 기사는 원문 제공 시각), `lastBuildDate`는 검색결과 생성 시각이다. 기사 제공 시각과 제품 조회 시각의 이름을 구별한다. 명세가 지정한 `<b>` 강조와 표시 문자만 안전하게 렌더링하고 원격 마크업을 실행하지 않는다. 정해진 필드나 원문 링크를 확인할 수 없는 응답은 정상 0건과 구분한다. [뉴스 검색 명세][search]
- **운영 한도.** 뉴스 명세는 일 25,000회로 적고, API HUB 사용 가이드의 FAQ는 NAVER 검색 카테고리 통합 **월 최대 775,000회**를 명시한다. 같은 FAQ는 키당 **50 RPS**, 검색 플랫폼 전체 **1,000 RPS**, 초당 한도 초과 시 `429`, 월 한도 도달 시 차단, 한시 무료와 유료 전환의 사전 공지를 안내한다. 한도 단위에 문서 간 차이가 있으므로 일 25,000회를 API HUB 운영 규칙으로 확정하지 않는다. 실제 Application 한도·과금·429 사유는 해당 콘솔과 제공자 안내에서 확인한다. [뉴스 검색 명세][search] · [API HUB 사용 가이드][guide]

## 검증 범위와 운영 확인 항목을 기록한다

- **과거 E-05.** 2026-11-09 기록에서 `광진구 분양`, `sort=date`, 요청 3건으로 내려온 최신순 3건과 제목·발췌·원문 URL·게시시각 필드의 확인을 추적했다. 80/80은 법령·교통·뉴스 세 서비스의 저장 응답 검사 전체다. 이번에는 공개 집계와 설정만 확인했다. [기존 검증 기록](validation-20261109.md#추가-3종을-구분한다) · [공개 검증 설정](probes.json)
- **합성 백엔드 검사.** 커넥터와 HTTP 검사 11건이 통과했다. 별도 합성 요청에서 `available` 응답의 제목·발췌·원문 링크·원본 도메인·시각·검색 조건과 응답 순서, `geographicRelevance`·`factVerification`의 `unverified`, `private, no-store`를 확인했다. 제공자 응답의 별도 전문 필드는 전달하지 않았다. [지역 뉴스 API](regional-news.md)
- **기존 진단.** `probe_apis.py --probe news_search`는 상태와 건수만 출력하며 결과 파일을 생성하지 않는다. `import_api_response.py`는 뉴스 응답의 신규 등록을 원본 파일을 읽기 전에 거절한다. 합성 검사에서 성공·인증 오류의 무저장과 일반 원문 `?doc=` 링크의 메모리 보존을 확인했다. [진단 CLI 회귀 검사](../../scripts/test_credential_sanitization.py)
- **즉시 표시.** 화면에서 결과 영역이 독립적으로 유지되는지, BI·원문 출처·원문 링크가 보이는지, 제공된 순위·내용이 유지되는지, 검색 발췌와 지역 관련성 미확인이 함께 보이는지 확인한다. 사실성·전문·지역 관련성은 검증하지 않았다. 이번 공개 웹 요청에서는 BI 가이드가 지정한 API HUB 포털 링크의 정상 이동을 확인하지 못했다. 화면 검수에서 공식 BI 링크와 원문 링크의 이동을 각각 확인한다. [API HUB 상표·BI 사용][brand]
- **활성화·추가 활용.** 담당자가 운영 환경의 NCP Application 등록·약관 동의·검색 뉴스 선택, 설정 한도와 요금, 화면 BI와 광고·수익화 조건을 확인한다. R-11의 저장·복원·PDF에 검색 결과를 포함할 필요가 있다면 제공자에게 해당 행위의 허용 범위와 기간을 서면으로 확인한다(D-07). 출처 문서의 독립 검증에는 인증 API 호출, 계정·키 검토, 기사 원문 조회가 포함되지 않았다. 개발 커넥터의 별도 확인 범위는 제품 API 문서에 기록한다. [지역 뉴스 API](regional-news.md)
