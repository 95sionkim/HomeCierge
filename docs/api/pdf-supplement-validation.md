# API·공고 PDF 결합 검증

**API의 구조화된 기본 정보에, 해당 회차의 공식 공고 PDF를 읽어 상세 정보를 보충한다.** 사용자가 2026-11-06 확정한 데이터 구성이다. 강변역 센트럴 아이파크 불법행위 재공급 공고 1건에 적용하여 PDF 12쪽을 확보하고, 46개 항목의 근거를 정리했다. 저장 원문·추출 결과·API 대조·금액 산술 등 72개 검사를 통과했다.

기존 [통합 검증 보고서](validation-20261109.md)는 API 자체가 제공하는 범위의 기록이다. 후속 PDF 결합 결과는 `pdf-evidence/2026930040/combined.json`에 별도로 저장하여 API 원문을 덮어쓰지 않는다. 이 공고는 2026-10-06 접수가 끝난 검증 사례다.

## 실제 계산 output

```json
{
  "base_price_krw": 1222020000,
  "required_balcony_price_krw": 21780000,
  "base_plus_required_balcony_krw": 1243800000,
  "contract_deposit_total_krw": 124380000,
  "balance_total_krw": 1119420000,
  "total_acquisition_cost_krw": null,
  "asking_price_krw": null,
  "eligibility_decision": null

```

분양가+승계 필수 확장비는 **12억4,380만원**, 계약 시 두 계약금 합계는 **1억2,438만원**, 잔금 합계는 **11억1,942만원**이다. 이 합계는 취득세·등기비·인지세·금융비용을 포함한 총취득비용이 아니다. 주택 잔금은11월30일까지, 확장비 잔금은입주시로 각각 근거를 보존한다.

위 코드는 읽기 쉬운 값 요약이다. 실제 `combined.json`은 `api_original`, 페이지·표 셀·인용문을 담은 `pdf_supplement`, 입력 필드와 산식을 담은 `derived`로 구분한다. 빈 값은 사실로 추정하지 않는다.

## 잘못된 공고 연결을 실제로 차단한 사례

사업주체 공식 홈페이지의 공고 다운로드는 같은 단지의 **6월 공고**로 연결되어 있었다. 청약홈의 해당 상세 페이지에서 **9월 공고 첨부**를 별도로 확보했다.

| 대조한 항목 | 대상9월 공고 | 다른 회차6월 공고 |
| --- | --- | --- |
| 주택관리번호 | 2026930040 | 2026930019 |
| 공고일 | 2026-09-23 | 2026-06-12 |
| 공급 수 | 1세대 | 2세대 |
| 대상 호실 | 101동402호 | 101동802호, 104동503호 |
| 84C 공급면적 | 105.8939㎡ | 105.8736㎡ |
| 옵션 | 발코니 확장, 무상 수납장 | 에어컨 등 다른 유상 옵션도 존재 |
| 연결 결과 | API와 일치하여 보충 허용 | 현재 공고번호·공고일 불일치로 거부 |

따라서 **단지명이 같거나 공식 사이트에 있다는 이유만으로 PDF를 결합하지 않는다.** 다른 회차의 PDF도 실제 파일로 보존해 거부 검사를 재현할 수 있게 했다. 최초 공고번호2024000226 역시 본문에 함께 등장하므로 문서에 나온 첫 번호를 무조건 채택하지 않는다.

## 추출과 병합 원칙

1. API 공고 식별자·공고일을 기준으로 공식 상세 페이지의 PDF를 확보한다. 원본 PDF, 다운로드 출처, SHA-256을 함께 보존한다.
2. 페이지별 텍스트와 표·셀 좌표를 추출한다. 텍스트가 없는 페이지는 OCR 검토 대상으로 남기며 빈 값을 사실로 간주하지 않는다.
3. 현재 공고를 지정하는 문장으로 번호·공고일을 대조한다. 미식별·중복·불일치이면 자동 병합을 차단한다.
4. 필요한 필드에 값·단위·원문·쪽수·표 셀을 연결한다. 이번 사례는 텍스트12쪽과 주요 가격표4·5쪽의 이미지 검수까지 수행했다.
5. API와 중복되는 면적·유형·공급 수·금액을 대조한다. 값이 다르면 출처와 시점을 함께 남기고 확인 전 계산을 차단한다.
6. 검증이 통과한 값으로만 합계를 계산한다. 주택형 최고금액을 모든 개별 호실의 가격으로 확대 적용하지 않는다.
7. 공고가 최초 공고·별도 안내를 참조하면 누락 자료 목록을 만든다. 참고 문서를 확보했다고 가정하지 않는다.

**현재 자동화 범위:** 텍스트·표 추출, 특정 현재 공고 식별 문장 탐지, 검수 항목의 원문 존재·정규화·API 일치·산술 검사와 병합. 46개 항목의 의미 선정·표 연결은 이 사례를 직접 검수한 결과다. 모든 형식의 공고에서 의미까지 자동 추출하는 기능은 아직 구현·평가하지 않았다.

표 추출만 신뢰하지 않아야 할 실제 사례도 있었다. 1쪽 표의 재당첨10년 셀이 추출 결과에서 누락되어 본문의3쪽 근거를 연결했다. 5쪽의 토지등소유자·임대 세대 표를 이번 재공급 물량으로 잘못 읽지 않도록 구분했다.

## 파일과 재현 방법

이 절의 원문·추출 파일은 비공개 로컬 증거이며 GitHub 저장소에 포함하지 않는다. 아래 역사적 검증 명령은 별도 자료가 필요하다. 새 체크아웃의 기본 테스트는 [개발 안내](../development.md)를 따른다.

| 파일 | 담은 내용 |
| --- | --- |
| `pdf-evidence/2026930040/notice.pdf` | 공식9월 공고 원본12쪽 |
| `source.json` | 출처 URL·해시·획득 경로 |
| `pages.json`, `text.txt` | 최초 페이지별 텍스트와 읽기용 텍스트 |
| `extracted.json` | 재실행 가능한 텍스트·표·셀 좌표와 식별 결과 |
| `reviewed-facts.json` | 46개 검수 항목과 페이지·표·원문 근거 |
| `combined.json` | API 원문+검증된 PDF 보충값+파생 계산 |
| `validation.json` | 72개 검사 결과와 다른 회차 거부 결과 |
| `pdf-evidence/2026930019/` | 잘못된 회차 연결을 차단하는 공식6월 PDF 증거 |

프로젝트 최상위에서 실행한다. 저장 데이터 병합 검증은 Python 표준 라이브러리만 사용하며 키·네트워크가 필요 없다.

```sh
python3 scripts/validate_pdf_supplement.py
```

PDF를 새로 추출하려면 PyMuPDF가 필요하다. 이번 실행 버전은1.26.5다. 추출 결과가 바뀌면 `reviewed-facts.json`의 근거와 추출 파일 해시를 다시 검수해야 하며, 기존 검수 승인을 자동으로 이어받지 않는다.

```sh
python3 -m pip install -r requirements-pdf.txt
python3 scripts/extract_notice_pdf.py pdf-evidence/2026930040/notice.pdf --output pdf-evidence/2026930040/extracted.json
python3 scripts/validate_pdf_supplement.py
```

OpenAI 키는 사용자가 저장한 설정의 존재만 확인했다. 이번 텍스트 PDF의 추출·계산은 로컬에서 수행했으며 **OpenAI 인증·모델 호출·LLM 자동 필드 추출은 테스트하지 않았다.** 이후 자동 추출 후보를 만드는 모델을 연결하더라도 문서 일치 검사와 원문 근거 검증은 유지한다.
