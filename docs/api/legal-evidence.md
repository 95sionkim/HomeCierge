# 공고일에 시행된 법령을 확인한다

선택한 공고의 모집공고일을 기준으로 「주택공급에 관한 규칙」의 시행본과 관련 조문 제목을 찾는다. 예를 들어 재공급 공고에서는 그날의 시행본을 연 뒤, 부칙에서 최초 모집공고일을 기준으로 삼는 경과조치가 있는지 확인할 수 있다. `available`은 판본을 확인했다는 뜻이다. 개인의 청약 자격과 예외 적용 여부는 사용자가 원문과 공고 조건을 함께 검토할 항목이다. [PRD R-17·A-37](../prd/01-product-prd.md) · [법제처 시행본의 부칙 예시](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=286965&efYd=20260615)

## 저장된 분석에서 읽는다

로그인한 사용자가 `GET /api/v1/analyses/{analysisId}/snapshots/{snapshotId}/legal-evidence`를 호출한다. 요청에는 사용자 JWT를 담는다. 날짜를 지정하는 매개변수는 없다. API가 소유권·분석 대상과 수집 상태를 확인한 뒤 공고 API에 기록된 `RCRIT_PBLANC_DE`를 사용한다. 수집을 실행한 날이나 실거래 조회 종료일은 공고일의 대체값으로 쓰지 않는다.

| 응답의 `status`를 읽는다 | 화면에 표시한다 |
| --- | --- |
| `available` | `noticeDate`를 기준일로, `reference.effectiveOn`을 시행일로 표시한다. 법제처 이름과 `sourceUrl`을 함께 보여주고 `articles[].label`과 `heading`으로 조문을 안내한다. |
| `version_unverified` | 공고일은 확인했다. 당시 판본이 등록될 때까지 공식 개정 이력(`historyUrl`)을 열어볼 수 있다. |
| `notice_date_unverified`, `selection_unverified` | 수집한 모집공고일 또는 선택한 공고·회차의 연결을 다시 확인한다. |
| `source_restricted` | 출처 이용 조건에 따라 법령 자료 표시가 보류됐다. 다른 분석 기능은 각자의 응답을 사용한다. |
| `synthetic_input` | 합성 공고를 선택한 상태다. 실공고 수집본을 선택하면 당시 판본을 조회할 수 있다. |

확인한 판본에는 법령 ID(`lawId`), 법령일련번호(`mst`), 공포일(`promulgatedOn`), 시행일(`effectiveOn`), 법령정보를 조회한 시각(`observedAt`)이 있다. 기본법령명으로 여는 주소는 현재 판본으로 바뀔 수 있어서 이 API는 일련번호와 시행일을 지정한 공식 본문 주소를 돌려준다. 부칙·경과규정(`transitionalProvisions`)과 예외(`exceptions`)는 `requires_review`이고, 개인 자격(`personalEligibility`)은 `not_assessed`다. 무순위·잔여세대 계열의 공고는 `nextActions`에서 최초 공고와 해당 회차의 조건도 함께 확인하도록 안내한다. [공식 시행일 본문 조회 명세](https://open.law.go.kr/LSO/openApi/guideResult.do?htmlName=lsEfYdInfoGuide)

미로그인은 401, 본인 분석과 연결되지 않은 수집본은 404, 잘못된 식별자·쿼리는 400이다. 백엔드 장애는 503으로 반환한다. 사용자 응답은 `private, no-store`다.

**내 분석 → 완료된 분석 → 법령 근거**에서 현재 실행에 연결된 수집본으로 요청한다. 시행본이 확인되면 모집공고일과 시행일을 나란히 보여주고, 공포일·법령일련번호·조문 제목과 해당 판본 원문을 표시한다. 해당 날짜의 판본이 게시되기 전에는 ‘당시 시행본 확인 필요’와 공식 개정 이력 링크를 제공한다.

## 작업자가 법령을 조회하는 시점을 정한다

공고 문서 작업에 `--with-law`를 붙이면 확인한 공고일로 법제처를 조회한다. `--save`까지 지정하면 공고 수집본을 저장한 뒤 해당 날짜의 법령 참조도 게시한다. 법령 조회가 실패해도 앞서 완료한 공고·납부 일정 작업은 성공으로 남으며 법령 상태를 따로 확인할 수 있다. 날짜 하나를 다시 수집할 때는 다음 명령을 사용한다.

```sh
python3 scripts/collect_law_evidence.py --live --date 2026-09-23
python3 scripts/collect_law_evidence.py --live --date 2026-09-23 --publish
```

작업자는 정확한 법령명으로 시행일 목록의 모든 페이지를 대조한다. 공고일까지 공포되고 시행된 후보에서 판본을 식별한 뒤 해당 일련번호와 시행일로 본문을 확인한다. 수집이 불완전하거나 판본을 식별하지 못하면 게시를 보류한다. 해당 시행본 안에서 공고·공급계약·공급대상·자격·재공급이 제목에 나타나는 조문을 찾아 그 번호와 공식 제목을 제공한다. 조문 제목이 일반적이거나 별표·부칙에서만 나오는 조건은 원문에서 더 확인해야 한다.

같은 공고일의 두 분석은 검증한 참조를 공유한다. 화면을 다시 열 때는 사용자 권한으로 그 날짜에 대해 가장 최근에 게시한 확인 결과를 읽는다. 원문 링크는 응답에 표시된 시행본에 고정된다.

법제처 개발용 인증은 작업자 환경에서 관리한다. 저장과 조회 시 출처 레지스트리의 허용 범위를 확인하고, 화면에서 법제처를 출처로 표시한다. [법제처 공동활용 이용안내](https://open.law.go.kr/LSO/information/guide.do)

## 같은 단지의 두 공고를 대조한다

2026년 11월 22일 청약홈 무순위·잔여세대 API에서 강변역 센트럴 아이파크의 두 공고일을 다시 조회했다. 공고 작업자의 `--with-law` 경로를 거쳐 법제처의 시행일 목록과 본문을 대조했고, 두 날짜의 판본 표지를 서울 개발 DB에 게시해 다시 읽었다.

| 공고일을 확인한다 | 당시 시행본을 연다 | 탐색할 조문 제목을 센다 |
| --- | --- | --- |
| 2026-06-12 · 공고 2026930019 | [2025-10-31 시행, MST 279483](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=279483&efYd=20251031) | 11건 |
| 2026-09-23 · 공고 2026930040 | [2026-06-15 시행, MST 286965](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=286965&efYd=20260615) | 11건 |

같은 단지라도 6월 15일 개정 전후의 두 공고는 서로 다른 판본을 열었다. 별도 검수에서 2024년 5월 31일을 기준으로 조회했을 때는 가장 늦은 시행일의 후보가 여러 건이었다. 이 날짜는 `law_version_ambiguous`로 보류했다. [공식 출처·이용 조건 검수](be-09-source-evidence.md)

11월 22일, 논산 공고 2026000540의 모집공고일인 2026-11-13으로 법제처를 조회해 서울 개발 DB에 게시했다. 개발 목록에서 01형을 선택해 완료한 새 분석으로 로그인한 브라우저에서 2026-06-15 시행본과 조문 제목 11개를 확인했다. 다른 계정으로 같은 수집본을 조회한 응답은 404였다. [당시 시행본](https://www.law.go.kr/LSW/lsInfoP.do?lsiSeq=286965&efYd=20260615)
