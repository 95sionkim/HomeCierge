# 과천 갈현동 실거래와 공식 주택형의 비교 검산

2026-11-22 한국시간 관측 · 비교 엔진 `comparison/v1` · [개발 계획 M2](../development-plan.md) · [지역·면적 판정 기준](../prd/01-product-prd.md#72-지역-검색과-비교-규칙)

**계약일을 2026-09-23 하루로 지정하면 과천 르센토 데시앙 84B와 같은 법정동에서 공급면적 기준을 충족한 다른 단지는 과천 푸르지오 라비엔오 하나였다.** 이 단지의 매매 1건은 20억 8,000만 원이다. 국토교통부 원문을 직접 집계한 건수·최저·중위·최고가가 비교 엔진과 일치했다. 같은 자료를 최근 1년으로 넓히면 갈현동 매매 25건 중 24건의 연결 근거가 더 필요하다. 아래의 하루 결과는 공식 공고와 거래를 같은 날 대조할 수 있어서 고른 사후 검증 사례다.

실거래 원행의 단지 일련번호 `41290-455`, 단지명, 법정동, 지번 `827`, 도로명 및 건물번호 `15`를 확인했다. 거래의 전용면적 `84.745`는 십진수로 공식 `84.7450`과 같다. 최초 공고의 전체 8개 주택형·679세대 중 이 값은 84D 한 유형에만 있다. 준공 후 두 공고에서도 동일한 84D 주택형과 공급면적이 확인된다. 최초 공고의 모델번호 `03`과 계약일 공고의 모델번호 `01`은 각 회차의 번호다. 연결 단위는 단지와 주택형이다. 재공급된 두 호실과 매매 호실의 개별 대응은 미확인이다. [청약홈 공고·주택형 API](https://www.data.go.kr/data/15098547/openapi.do)

대상 공급면적의 ±5% 구간은 양 끝을 포함한 **104.31969~115.30071㎡**다. 비교 단지의 110.3239㎡는 구간 안에 있고 공급면적 차이는 **0.5137㎡**다. K-apt는 단지 식별에만 사용했다. 공급면적은 표에서 전용과 주거공용을 더해 각각 검산했다.

## 3. 하루의 전체 거래와 수작업 통계를 대조한다

기준일은 2026-11-22로 고정했다. 국토교통부 두 서비스에 `LAWD_CD=41290`, `DEAL_YMD=202609`, `numOfRows=1000`을 요청했다. 매매 14행, 권리 3행 모두 1쪽에 도착했고 `totalCount`와 행 수가 같았다. 엔진과 독립된 XML 판독에서 계약 연·월·일을 달력 날짜로 만들고 9월 23일만 남겼다. 이 날짜에는 매매 1행, 권리 0행이다. 매매의 해제 표시·해제일은 공란이었다. 신고 금액의 단위인 만원을 원으로 환산했다. [국토교통부 아파트 매매 실거래가](https://www.data.go.kr/data/15126468/openapi.do) · [국토교통부 아파트 분양권전매 실거래가](https://www.data.go.kr/data/15126471/openapi.do)

| 아파트 매매 | 1 | 각각 2,080,000,000원 | `confirmed` · 건수와 세 금액 일치 · `smallSample=true` |

BE-02의 `ingest`에 조회한 공고·주택형, 원문에서 점검한 대상 공급면적, 월별 거래를 전달했다. BE-05의 `compare_snapshot`에는 단지·지역 식별과 계약일이 입증된 매매 1행의 근거만 넣었다. 나머지 16행은 거래기간 밖으로 제외됐다. 결과는 `completeness=complete`, 우선 법정동 후보 1개, 미해소 0행, `rankingComplete=true`, `expansion=null`이다. 대상 공고의 호실 분양가·필수 옵션은 이 검산에서 입력하지 않아 `noticePrice`는 `no_confirmed_room_subtotal`로 보류됐다. 비교 가격은 거래 통계다.

## 4. 기간을 넓혀 보류를 확인한다

세 실행 모두 공고와 선택 주택형, 지역 우선순위, ±5%와 거래 근거를 그대로 뒀다. 9월 23일에 확인된 면적을 같은 단지의 다른 계약일로 옮겨 붙이지 않았다.

| 계약일 범위(양끝 포함) | 과천시 응답 | 갈현동의 확인분과 보류 | 비교 결과 |
| --- | --- | --- | --- |
| 2026-09-23 하루 | 9월 매매 14행·권리 3행 | 매매 1건 확인, 보류 0 | 확인 통계 · 우선 범위 완료 |
| 2026-09-01~09-30 | 같은 17행 | 매매 1건 확인, 다른 갈현동 매매 1건 단지 연결 보류 | 잠정 통계 · 순위 미완료 |
| 기본 최근 1년 2025-11-23~2026-11-22 | 13개월 매매 267행·권리 17행. 수집 단위 26개 중 완료 20개·정상 빈 응답 6개 | 기간 밖 4행, 해제 9행, 다른 동 246행을 제외하면 갈현동 매매 25행. 1건 확인, 24건 단지 연결 보류 | 잠정 통계 · 순위 미완료 |

기간을 넓힌 두 실행에서도 갈현동의 분양권·입주권은 각각 정상 0건이고, 우선 범위에 매매 후보가 있어 시 전체로 확대하지 않았다. 최근 1년 중 나머지 24건이 ±5% 밖이라는 근거는 없다. 아직 검증하지 않은 항목은 복수 매매의 중위수, 권리 가격 양성 사례, 복수 후보의 면적·거리 동률, 운영에서의 자동 근거 연결이다. 기존 구의동 사례의 319행 보류도 독립된 결과로 남는다. [구의동 보류 검산](be-06-area-case.md)

## 5. 관측을 재현한다

아래 명령은 공공데이터포털의 청약홈·아파트 매매·분양권전매 API를 이용할 수 있는 `DATA_GO_KR_SERVICE_KEY`가 작업자 환경에 있을 때 수동 실행한다. K-apt 기본정보도 같은 키로 읽는다. 원문·인증값을 출력하거나 파일로 저장하지 않는다. 관측 후의 정정 신고·공고 교체가 있으면 같은 자료인지 다시 확인한다.

```sh
python3 scripts/verify_gwacheon_comparison.py --live
# 하루·한 달·기본 1년을 한 번에 대조하며 같은 응답은 재사용한다.
python3 scripts/verify_gwacheon_comparison.py --live --window all
```

각 명령은 원문 PDF가 사람이 표를 확인한 판본과 해시가 같은지 검사한 뒤, 거래 XML의 날짜·취소·금액을 직접 검산한다. BE-02 수집과 BE-05 비교에도 같은 응답을 전달한다. 매번 새로운 PDF에서 자동으로 주택형을 추출하거나 역사적 근거를 생성하는 기능은 별도다. 이용량은 실행당 공공데이터 API 상한 38회(K-apt 2회 포함), 청약홈 상세·첨부 상한 12회, 행정표준코드 전체자료 다운로드 최대 3회다.

2026-11-22 16:31~16:36 KST에 수집한 9월 매매 XML의 SHA-256은 `94878ea2f30022319a0285e116a13d90333dda342ba64455de8cb0f9b3d47d9b`, 권리 XML은 `d3ac4f80a0915857b973e0123c595a232b8dfb69bbcd4ac7fa888df923d76713`이다. 4개 PDF는 청약홈 상세에서 공식 첨부 식별자와 공고일을 대조했고 각 판본의 전체 해시는 [재현 명령의 입력](../../scripts/verify_gwacheon_comparison.py)에 기록했다. 행정표준코드 법정동 전체자료 TXT 해시는 `962fd4cdfb6ccf2887b745eb97db55f71112b9f9a32c1f8fbd7692fb069b1df0`이다. 공식 PDF와 실거래 원문은 저장소에 포함하지 않는다.
