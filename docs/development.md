# 개발 시작 안내

## 현재 개발 자산을 확인한다

PRD와 API 접근·필드·페이지 수집·주소 연결 검증 코드가 준비돼 있다. 웹 앱, 서비스 API, 데이터베이스, 인증, 배포 환경, LLM 구성은 아직 없다. 이 저장소의 Python 도구는 검증 자산이며 제품 기술 스택을 확정한 결과가 아니다.

기준 문서는 [PRD v0.1](prd/01-product-prd.md)이다. 지역 정책은 동→구이며 `validate_comparable_links.py`의 5km·전용면적 ±1㎡는 역사적 시험 조건이다.

## 첫 실행을 완료한다

기본 검사에는 외부 패키지가 필요 없다. 로컬 인계 검사는 Python 3.9.6에서 실행하며, GitHub Actions는 Python 3.11·3.13을 대상으로 한다. 지원 런타임의 제품 정책은 아직 미정이다.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m unittest discover -s scripts -p 'test_*.py' -v
python scripts/check_repository.py
python -m compileall -q scripts
python scripts/collect_recent_trades.py --probe apt_trade --lawd-cd 11215 --start 202511 --end 202610 --dry-run
```

예상 범위는 수집 경계 18개·주소 경계 8개, 합계 26개다. 모든 테스트 자료는 합성이고 실호출은 없다. `--dry-run`의 12개월은 과거 수집 범위를 재현하는 예시이며 제품의 ‘사용일 기준 최근 1년’ 날짜 정책을 확정하지 않는다.

실제 호출 설정은 [API 안내](api/README.md)를 따른다. `--check-config`는 설정 유무만 확인하며 인증 성공을 검증하지 않는다. 자동 검사에 실제 키를 등록할 필요가 없다.

## 코드 역할을 구분한다

| 파일을 찾는다 | 재사용할 역할을 확인한다 | 실행 조건을 확인한다 |
| --- | --- | --- |
| `scripts/probe_apis.py` | 공식 호스트 제한, 인증값 제거, JSON/XML 해석, 오류·정상 0건 구분 | 실호출에는 서비스 인증값 필요 |
| `scripts/collect_recent_trades.py` | 월·페이지 완전성, 만원→원, 계약일·해제·권리 종류 정규화 | `--dry-run`은 무호출; 실제 수집은 공공 API 키 필요 |
| `scripts/store_api_key.py` | 숨김 입력, 키별 로컬 파일 저장 | 대화형 터미널에서만 사용 |
| `scripts/import_api_response.py` | 직접 저장한 공식 응답을 출처·해시와 등록 | 보관 권한을 확인한 로컬 파일 필요 |
| `scripts/extract_notice_pdf.py` | PDF 페이지·표·셀·현재 공고 식별 문장 추출 | 로컬 PDF와 선택 의존성 필요 |
| `scripts/validate_api_evidence.py` | 과거 19응답의 162개 검사 | 원 프로젝트의 비공개 증거 필요 |
| `scripts/validate_pdf_supplement.py` | 과거 PDF/API 병합 72개 검사 | 원 PDF·추출·검수·API 자료 필요 |
| `scripts/validate_additional_services.py` | 과거 법령·교통·뉴스 80개 검사 | 비공개 증거와 이용 조건 확인 필요 |
| `scripts/validate_comparable_links.py` | 과거 반경 연결 재현, 지역·지번·도로주소 함수 | 전체 실행은 비공개 증거 필요; 경계 함수 테스트는 독립 실행 |
| `scripts/test_*.py` | 부분 수집·취소·권리 종류·주소 오연결 방지 | 합성 자료, 키·네트워크 불필요 |

전체 서비스용 재시도·동시성·캐시·쿼터·운영 로그는 아직 설계되지 않았다. 수집 완료는 조회 시점의 해당 요청 범위가 완료됐다는 뜻이며 지연 신고·정정 종료나 최종 비교 가능을 뜻하지 않는다.

## 첫 개발 과제를 진행한다

아래 순서는 개발 제안이며 미정값을 확정하지 않는다. PRD의 결정과 연결해 변경 이력을 남긴다.

| 과제를 진행한다 | 만들 결과를 정한다 | 선행 결정과 완료 조건을 확인한다 |
| --- | --- | --- |
| 1. 비교 성립 조건 | 한 공고·한 주택형의 수작업 기준 결과와 면적 연결 근거 | D-01. 대응 근거 없는 공급면적은 미확인으로 남김 |
| 2. 데이터 계약 | 공고·주택형·분석 조건·거래 스냅샷·단지 연결의 스키마 | R-01~R-03·R-06~R-09. 출처·단위·충돌·완료 상태 보존 |
| 3. 지역 상태 흐름 | 동 유지·보류·구 확대·구 자료 부족을 구분하는 로직 | D-02·D-03. A-03~A-13을 현행 정책으로 새로 검증 |
| 4. 첫 화면 흐름 | 입력→주택형 선택→비교·근거 결과 | D-04. 특정 공고 검토와 조건 기반 공고 발견 중 범위 결정 |
| 5. 대화·프로필 | 다중 채팅, 분석별 조건, 변경안 승인·거절·취소 | D-06. A-15~A-17, 미응답은 기존 값 유지 |
| 6. 보조 기능·운영 | 채택한 법령·교통·자금 기능과 배포 준비 | D-07·채택 기능 수락 기준. API 성공을 운영 승인으로 확대하지 않음 |

화면·서버·DB·LLM 스택을 정하기 전에도 출처·단위·실패 상태의 스키마와 사용자 흐름 설계는 진행할 수 있다. 공급면적 기준을 전용면적으로 바꾸거나 후보 순위를 거리순으로 정하는 것은 별도 결정이다.

## 변경을 검토한다

요구 변경은 관련 R/D/A를 함께 수정하고 미정 결정의 채택 근거를 남긴다. 코드 변경에는 해당 실패·경계 동작을 검증하는 테스트를 적용한다. 제품 수락 기준 17개는 아직 통과한 제품 테스트가 아니며 구현과 함께 별도 검수한다.

실제 키·원자료·보고서 생성물은 커밋하지 않는다. 제3자 데이터의 출처·재사용 조건은 [데이터 관리 안내](data-handling.md)에서 확인한다. GitHub Actions의 Action 버전은 [checkout](https://github.com/actions/checkout)·[setup-python](https://github.com/actions/setup-python) 공식 사용법을 참고했다.
