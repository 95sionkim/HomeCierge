# 개발 시작 안내

## 현재 개발 자산을 확인한다

PRD와 API 접근·필드·페이지 수집·주소 연결 검증 코드가 준비돼 있다. 2026-11-11 사용자 선택에 따라 서울의 Supabase 개발 DB에 스키마·RLS·프로필 승인 함수를 적용하고 Vercel 인증 조회 API를 보호된 Preview로 배포했다. 원격 DB의 합성 역할 검사·롤백과 배포 HTTP 응답을 확인했다. 실제 가입·로그인·세션 갱신과 화면 통합은 후속 검수다. 웹 화면·공고 처리·비교 엔진·LLM 구성은 구현하지 않았으며 화면은 별도 팀이 제작한다. Python 도구는 과거 검증 자산으로 유지한다.

DB·배포 작업은 [인프라 준비](infrastructure.md), 화면 팀의 연결은 [인계 계약](frontend-handoff.md)을 따른다. Node.js 26에서 `npm ci`, `npm run build`, `npm test`, `npm run test:db`로 새 기반을 검사한다. 기본 검사는 실제 클라우드 계정·인증값 없이 실행한다.

`npm run dev`는 `http://127.0.0.1:3001`에서 배포와 같은 요청 처리기를 실행한다. 인증 DB 조회에는 `.secrets/backend.env`의 연결값이 필요하다. Git 자동 배포는 아직 연결하지 않았으므로 클라우드 프로젝트 생성과 저장소 반영을 구분한다.

기준 문서는 사용자 결정 36개를 반영한 [PRD v1.0](prd/01-product-prd.md)이다. 지역 정책은 동·읍·면 우선→전체 정상 0개이면 구 또는 구 없는 시·군 확대다. `validate_comparable_links.py`의 5km·전용면적 ±1㎡는 역사적 시험 조건이며 현행 구현으로 사용하지 않는다.

## 첫 실행을 완료한다

기본 검사에는 외부 패키지가 필요 없다. 로컬 인계 검사는 Python 3.9.6에서 실행하며, GitHub Actions는 Python 3.11·3.13을 대상으로 한다. 지원 런타임의 제품 정책은 아직 미정이다.

```sh
python3 -m venv .venv
source .venv/bin/activate
python -m unittest discover -s scripts -p 'test_*.py' -v
python scripts/check_repository.py
python -m compileall -q scripts
python scripts/collect_recent_trades.py --probe apt_trade --lawd-cd 11215 --start 202511 --end 202610 --dry-run
```

예상 범위는 수집 경계 18개·주소 경계 8개, 합계 26개다. 모든 테스트 자료는 합성이고 실호출은 없다. `--dry-run`의 12개월은 과거 수집 범위를 재현하는 예시다. 현행 제품은 조회일까지 최근 1년과 당월 포함을 요구하므로 해당 월들을 수집한 뒤 정확한 계약일 범위로 걸러야 한다. 예시 명령을 제품 기본 기간으로 사용하지 않는다.

실제 호출 설정은 [API 안내](api/README.md)를 따른다. `--check-config`는 설정 유무만 확인하며 인증 성공을 검증하지 않는다. 자동 검사에 실제 키를 등록할 필요가 없다.

## 코드 역할을 구분한다

| 파일을 찾는다 | 재사용할 역할을 확인한다 | 실행 조건을 확인한다 |
| --- | --- | --- |
| `scripts/probe_apis.py` | 공식 호스트 제한, 인증값 제거, JSON/XML 해석, 오류·정상 0건 구분 | 실호출에는 서비스 인증값 필요 |
| `scripts/collect_recent_trades.py` | 월·페이지 완전성, 만원→원, 계약일·해제·권리 종류 정규화 | `--dry-run`은 무호출; 실제 수집은 공공 API 키 필요 |
| `scripts/store_api_key.py` | 숨김 입력, 키별 로컬 파일 저장 | 대화형 터미널에서만 사용 |
| `scripts/import_api_response.py` | 직접 저장한 공식 응답을 출처·해시와 등록 | 보관 권한을 확인한 로컬 파일 필요 |
| `scripts/extract_notice_pdf.py` | PDF 페이지·표·셀·현재 공고 식별 문장 추출 | 로컬 PDF와 선택 의존성 필요 |
| `scripts/validate_api_evidence.py` | 과거 19응답의 162개 검사 | 원 프로젝트의 비공개 증거 필요 |
| `scripts/validate_pdf_supplement.py` | 과거 PDF/API 병합 72개 검사 | 원 PDF·추출·검수·API 자료 필요 |
| `scripts/validate_additional_services.py` | 과거 법령·교통·뉴스 80개 검사 | 비공개 증거와 이용 조건 확인 필요 |
| `scripts/validate_comparable_links.py` | 과거 반경 연결 재현, 지역·지번·도로주소 함수 | 전체 실행은 비공개 증거 필요; 경계 함수 테스트는 독립 실행 |
| `scripts/test_*.py` | 부분 수집·취소·권리 종류·주소 오연결 방지 | 합성 자료, 키·네트워크 불필요 |

전체 서비스용 재시도·동시성·캐시·쿼터·운영 로그는 아직 설계되지 않았다. 수집 완료는 조회 시점의 해당 요청 범위가 완료됐다는 뜻이며 지연 신고·정정 종료나 최종 비교 가능을 뜻하지 않는다.

기존 리뷰에서는 인증값 정제의 조건부 응답 손상·이스케이프 제거 누락과 역사적 연결기의 누락 ID 정렬 실패를 합성 자료로 재현했다. 이 PRD 작업에서 코드를 수정하지 않았다. 추가 실호출 전 정제 결함을, 역사적 연결기 재사용 전 정렬 결함을 수정·회귀검사한다. 기존 26개 테스트 통과가 이 결함을 해소한 것은 아니다. [리뷰 보완 추적표](prd/03-review-resolution.md)

## 첫 개발 과제를 진행한다

아래 순서는 개발 제안이며 미정값을 확정하지 않는다. PRD의 결정과 연결해 변경 이력을 남긴다.

| 과제를 진행한다 | 만들 결과를 정한다 | 선행 결정과 완료 조건을 확인한다 |
| --- | --- | --- |
| 1. 비교 성립·사용자 흐름 | 대표 공고의 수작업 결과와 공급면적·권리 식별·지역 코드의 근거 표 | D-01·D-02. 연결 성공/보류와 분모를 기록하고 D-05 사용자 이해·보완 부담 확인을 초기 화면 설계와 병행 |
| 2. 데이터 계약 | 공고·주택형·분석 조건·거래 스냅샷·단지 연결의 스키마, 공식 PDF 자동 확보·업로드 보완·값별 자동 점검 | R-01~R-03·R-06~R-09. 출처·단위·충돌·완료 상태 보존. A-30~A-32·A-59와 유형별 자동 점검 검증 |
| 3. 지역 상태 흐름 | 동·읍·면→구 또는 시·군, 전체 5개 자동/직접 선정, ±5% 안의 최근접 면적·직선거리, 최소 1건·자체 거래·기간·호실 가격 | D-01~D-03. A-03~A-13·A-21~A-26·A-39~A-42·A-53~A-55·A-57을 현행 정책으로 검증 |
| 4. 첫 화면 흐름 | 시·군·구·예산과 선택 공급면적·입주 월 범위→접수일 정렬·충족/확인 필요 목록→한 공고·한 주택형 분석 | R-11·R-15·D-04. 같은 주택형·호실에서 모든 조건을 충족하는 항목 확인. A-18~A-20·A-27~A-29·A-33~A-35·A-47~A-50 검증 |
| 5. 대화·프로필·보고서 저장 | 첫 로그인·계정 격리·기기 간 복원·공유/분석별 입력 분리·삭제·보고서 PDF와 설명 일치 | D-06. A-15~A-17·A-43~A-45·A-51·A-56·A-58, 승인·보존·삭제 상태와 출력 정합성 검증 |
| 6. 보조 기능·운영 | 보유·추가 자금과 확정/예상 구분·납부 대조, 법령 근거, 대중교통·도보·자동차 경로 및 배포 준비 | R-16~R-18·A-36~A-38·A-46·A-52. 자동차 경로 소스·연동과 D-04·D-06·D-07의 운영 조건 검증. 기존 API 성공을 자동차·전체 운영 승인으로 확대하지 않음 |

DB·배포 기반은 Supabase·Vercel로 정했고 화면 프레임워크·LLM은 미정이다. 출처·단위·실패 상태의 계약과 사용자 흐름 설계는 계속 보완한다. 공급면적 차이 우선·직선거리 차순위를 유지한다. 대표 좌표·완전 동률·거리 미확인 등 미정 세부 기준은 D-03에서 정하며 과거 5km 도구의 반경 제한을 그대로 채택하지 않는다.

## 변경을 검토한다

요구 변경은 관련 R/D/A를 함께 수정하고 미정 결정의 채택 근거를 남긴다. 코드 변경에는 해당 실패·경계 동작을 검증하는 테스트를 적용한다. 제품 수락 기준 59개는 아직 통과한 제품 테스트가 아니며 구현과 함께 별도 검수한다. 소스별 보관·PDF 내보내기 조건, 자동차 경로와 대표 사용자 검토는 PRD §12의 완료 근거를 남긴다.

실제 키·원자료·보고서 생성물은 커밋하지 않는다. 제3자 데이터의 출처·재사용 조건은 [데이터 관리 안내](data-handling.md)에서 확인한다. GitHub Actions의 Action 버전은 [checkout](https://github.com/actions/checkout)·[setup-python](https://github.com/actions/setup-python) 공식 사용법을 참고했다.
