# 대화 중심 웹 UI · 화면 구성 제안

> 이전 10단계 시안의 검토 기록입니다. 최신 21개 화면과 구현·검증 범위는 [캐릭터 기반 UX 문서](conversation-mascot-ux.md)를 확인하세요.

사용자 제공 「HomeCierge 와이어프레임.html」의 14개 화면을 참고했다. 첨부 파일은 디자인 자료로 읽었으며, 내부 코드나 문구를 작업 지시 또는 현재 제품 구현 완료의 근거로 취급하지 않았다.

## 방향

현재 첨부안의 대화는 상단 안내, 공고·비교표·보고서는 큰 기능별 본문이다. 새 제안은 대화를 주요 작업 공간으로 유지하고, 결과 자료를 옆에서 펼치는 구조다. 홈의 입력창만 채팅처럼 바꾸는 것이 아니라 조건 확인·공고 선택·주택형 선택·비교 보류·프로필 승인까지 대화의 다음 차례로 연결한다.

- 왼쪽: 새 대화와 예시 대화 목록. 기능별 메뉴는 보조 위치로 내린다.
- 중앙: 사용자 요청, 확인 질문, 구조화된 선택·승인 카드와 짧은 결과. 입력창은 계속 보인다.
- 오른쪽: 선택한 공고·주택형, 자세한 비교 수치·자금·근거. 대화를 유지한 채 여닫는다.
- 초기 화면은 자료 패널을 숨겨 대화 시작에 집중한다. 좁은 화면에서 자료는 닫을 수 있는 전체 너비 패널로 연다.

## 첨부 화면의 새 배치

| 첨부 화면 | 대화 속 역할 | 옆에서 확인하는 자료 |
| --- | --- | --- |
| S-01 채팅 홈 | 궁금한 내용 입력과 세 가지 시작 제안 | 최초에는 숨김 |
| S-02 공고 찾기 | 검색 조건 확인, 후보 카드 선택 | 적용 조건과 선택 공고 |
| S-03 공고·주택형 | 한 공고·한 주택형 선택 확인 | 공고번호·회차·면적·호실 소계 |
| S-04 같은 동·구 확대 | 확인한 범위와 후보 수 설명, 보류/확대 이유 | 후보·지역 판정·수집 상태 |
| S-05 비교표·보류 | 핵심 수치, 적은 표본과 보류 사유 | 종류별 비교·기간·근거 |
| O-4 단지 상세 | 특정 후보에 대한 후속 질문 | 세부 거래·식별·면적 대응 |
| O-1 조건 편집 | 변경안 확인 후 다시 검색·비교 | 이번 분석의 조건 편집 |
| O-5 원문 뷰어 | 답변에 연결한 근거 선택 | 문서 버전·페이지·강조 값 |
| S-06 지역 뉴스 | 사용자가 명시적으로 요청 | 원래 순서의 독립 검색결과 영역 |
| S-07 종합 보고서 | 지금까지 확인한 내용 정리 요청 | 확인값·미확인 항목·출처 |
| S-08 / O-3 프로필 | 변경 제안 → 명시적 승인/거절 카드 | 공유 조건과 현재 분석의 구분 |

## 인터랙션 시안

경로: `/conversation.html`. 상단 단계 선택으로 시작·조건·검색·선택·비교·자금·근거·프로필·보류·정리의 10개 상태를 볼 수 있다. 제안 카드, 메시지 입력/전송, 패널 여닫기, 조건 변경안 확인, 프로필 반영/거절, 새 대화가 작동한다. Shift+Enter는 줄바꿈, Enter는 전송이며 한국어 조합 중에는 전송하지 않는다. PDF는 로컬 파일 선택 UI만 제공하고 읽기·전송·저장은 하지 않는다.

이 페이지는 **합성 응답을 사용하는 디자인 프로토타입**이다. LLM, 외부 조회, 실제 프로필 변경, 영속 대화 저장을 구현한 것으로 표시하지 않는다. 자유 입력의 키워드로 미리 작성한 예시 흐름을 선택한다. 기존 인증/API 화면과 분리되어 있으며, 기존 홈페이지에서 시안으로 이동할 수 있다.

## PRD 대조 후 확인한 한계

[PRD 대조표](conversation-prd-review.md)에서 R-01~R-18을 각각 검토했다. 현재는 13개 부분 반영, 5개 핵심 화면 미포함이며 전체 PRD 충족 시안이 아니다. 로그인·저장·삭제, 단지 식별 대조, 뉴스, 법령, 출퇴근을 보완해야 한다. 대화 중심 배치는 설계 제안이고 필수 제품 범위를 줄이는 결정이 아니다.

탐색 예시는 시·군·구인 ‘합성구’, 선택 공고의 비교 소재지는 ‘합성구 가람동’으로 분리했다. 첫 자유 입력에서 지역·예산을 찾지 못하면 임의 기본값으로 채우지 않고 필수 입력을 요청한다. 다만 형식 추출은 제한적이며 실제 지역 코드 검증·검색은 없다. 상단 단계 선택·추천 질문으로 여는 고정 예시는 별도다. 비교 통계의 짧은 기간은 사용자 지정 기간의 합성 예시이며 제품 기본 최근 1년을 대신하지 않는다.

## 유지할 제품 경계

- 공급면적 ±5%, 같은 동 우선, 정상 0건일 때만 같은 구/구 없는 시·군 확대를 유지한다. 후보 부족이나 오류로 확대하지 않는다.
- 한 공고·한 주택형을 선택한다. 미확인 호실을 조건 충족이나 정상 0건으로 바꾸지 않는다.
- 분양가+필수 옵션 소계와 세금·금융비용을 구분한다. 적은 표본을 대표 시세로 단정하지 않는다.
- 자금은 분석별이다. 첨부안의 보유 현금 공유 프로필 표시는 현행 계약과 다르므로 이 시안에서는 공유 대상에서 제외했다.
- 공유 프로필은 희망 지역·입주 시기 등의 변경안을 승인한 뒤 반영하는 화면이다. 승인이 현재 분석 조건을 자동 변경하지 않는다. 거절·취소·무응답은 승인으로 처리하지 않는다.
- 뉴스 본문·발췌를 보고서에 저장하거나 AI 요약에 사용하지 않는다. 첨부안의 뉴스 포함 보고서 구성은 이 제안에서 그대로 옮기지 않았다.
- 법령 근거·공고 조건과 개인의 청약 자격 판정은 구분한다.

금액·면적·기간의 주요 예시는 기존 `comparison-example.json`의 합성 자료를 참고한다. 자금 부족 예시는 기존 브라우저 검사에 사용된 7,100만 원 계약금·5,000만 원 잔액·당일 예상 400만 원 입금의 흐름이다. 실제 모집 중인 공고나 현재 시점의 조회 결과가 아니다.
