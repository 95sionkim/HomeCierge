# HomeCierge PRD v1.0 리뷰 보완 추적표

2026-11-10 작성. [제품 PRD v1.0](01-product-prd.md)은 [사용자 결정 36개](02-decision-log.md)를 반영한 요구 기준본이다. 이 표는 2026-11-09의 독립 리뷰 14건과 코디네이터 재검토를 현행 요구·수락 기준·남은 작업에 연결한다. 정책 확정, 명세 보완, 실제 구현·자료 검증을 구분한다.

원 리뷰는 로컬 `reports/reviews/2026-11-09-claude-opus55-max.md`, 교차검토와 합성 경계 재현은 `2026-11-09-coordinator-synthesis.md`·`2026-11-09-coordinator-validation.json`에 보존돼 있다. 해당 기록은 Git 추적 대상이 아니다. v1.0 작성은 외부 API 재호출·사용자 조사·새 제품 수락 검사 통과를 뜻하지 않는다.

## 2. 구현 전에 준비할 근거를 정한다

1. **도구 결함을 먼저 수정한다.** 정제는 정상 JSON/XML·일반 텍스트를 보존하면서 직접값·인코딩·이스케이프 반향을 모든 저장·로그 경로에서 제거해야 한다. 짧은 인증값의 정제를 생략하는 처방만으로 해결하지 않는다. 역사적 연결기는 누락 ID와 유효 ID가 섞여도 보류 분기에 도달해야 한다.
2. **공급면적·권리·지역의 근거 표를 만든다.** 출처·식별자·면적 정의·시점·복수 대응과 검토 후보의 분모·성공/보류/불일치를 기록한다. 동·읍·면과 구 없는 지역의 코드 관계도 검증한다. 공급면적 자료가 없는 상태에서 전체 보류율이나 실제 비교 성공률을 추정하지 않는다.
3. **대표 공고의 기준 결과를 준비한다.** 초기 지원 유형, 여러 주택형·호실·필수 옵션·납부 일정, 같은 회차 정정과 참조 문서 사례를 포함한다. 수작업 검수 결과와 자동 점검 결과를 구분한다.
4. **새 자동차 경로와 저장·내보내기 조건을 검증한다.** 기존 대중교통 경로 기록을 자동차 지원 근거로 쓰지 않는다. 공공 API·PDF·K-apt·카카오·법령·뉴스·교통 자료별 보관·재사용·LLM 입력·PDF 표시 계약을 정한다.
5. **초기 흐름과 사용자 가치를 함께 확인한다.** 기준 보고서에서 가격 구성·지역/면적 범위·작은 표본·보류 사유가 이해되는지 확인한다. 조사 설계·분모·목표는 D-05에서 정하며 이번 문서 정리를 사용성 검증으로 간주하지 않는다.

## 3. 확정하지 않은 설계 세부를 유지한다

기술 스택·모델, 실제 공급면적 자료의 우선순위와 복수 대응 해소, 윤일·시간대 경계·갱신 주기, 면적/단지 동률·대표 좌표·거리 미확인, 자금의 같은 날 유입과 납부 처리, 경로 시간 조건, 인증 수단·승인 버전·삭제 구현, 성능·비용 목표는 D-01~D-07에서 계속 추적한다. 제품 정책을 구현하기 위한 이 값들을 구현 완료나 사용자 채택 값으로 조용히 바꾸지 않는다.

기존 검증 근거 E-01~E-06과 과거 5km 시험은 원래 검증 범위로 보존한다. v1.0의 범위가 넓어졌다는 이유로 과거 검사 통과의 의미를 확대하지 않는다.

## 4. 문서 통합 검사를 기록한다

2026-11-10에 기존 오프라인 테스트 26개와 저장소 기본 검사(추적 파일 32개)가 통과했다. 변경·추가한 문서 9개의 내부 파일 링크 42개, 표 구조, 요구 ID와 상호 참조를 별도로 확인했다. Q-01~Q-36은 모두 답변을 반영했으며 R 18개·P 6개·D 7개·E 6개·A 59개의 식별자가 연속된다.

E-01~E-06의 검증 결과 행은 기준 커밋 `857a2ff`와 같고, 이번 작업에서 제품 코드·테스트·CI를 변경하거나 외부 API를 호출하지 않았다. 이 검사는 문서의 정합성과 기존 도구의 회귀 확인이며 제품 기능 59개 시나리오의 통과, 사용자 가치 검증, 앞서 기록한 코드 결함의 수정 완료를 뜻하지 않는다.
