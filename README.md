# HomeCierge

희망 지역·예산으로 청약 공고를 찾고, 한 번에 한 공고·한 주택형의 분양 조건을 아파트 실거래와 비교하는 의사결정 지원 서비스입니다. **같은 동·읍·면을 우선 비교하고 정상 0개일 때 같은 구, 구가 없으면 같은 시·군으로 확대**합니다.

**사용자 결정 36개를 반영한 PRD v1.0 기준본**을 정리했습니다. 2026-11-11에는 서울의 Supabase 개발 DB를 생성해 스키마·RLS·프로필 승인 함수를 적용하고, 화면과 독립적인 Vercel Preview API를 배포했습니다. 로컬 46개 검사와 실제 DB의 권한 검사·배포 응답을 확인했습니다. 제품 화면은 별도 팀이 담당하며 실제 로그인·화면 통합은 후속 검수입니다. 2026-11-09의 10서비스·14조회는 과거 데이터 접근 근거이고 공고 검색·공급면적 비교·보고서·보조 기능의 구현 완료를 뜻하지 않습니다.

## 바로 실행하기

기본 테스트는 Python 표준 라이브러리만 사용합니다. API 키·네트워크·실제 응답 파일 없이 실행할 수 있습니다.

새 DB·API 기반은 Node.js 26에서 `npm ci`, `npm run build`, `npm test`, `npm run test:db`로 검사합니다. 패키지 설치 후 검사는 실제 클라우드 계정·인증값 없이 실행합니다.

화면 연동용 로컬 API는 `npm run dev`로 실행합니다. DB 연결값은 `.secrets/backend.env`에 저장하며 [화면 팀 연결 계약](docs/frontend-handoff.md)의 환경변수와 권한을 따릅니다.

```sh
git clone https://github.com/95sionkim/HomeCierge.git
cd HomeCierge
python3 -m unittest discover -s scripts -p 'test_*.py' -v
python3 scripts/check_repository.py
python3 scripts/collect_recent_trades.py --probe apt_trade --lawd-cd 11215 --start 202511 --end 202610 --dry-run
```

합성 자료의 **수집 경계 18개·주소 경계 8개 테스트**와 저장소 구성을 검사합니다. 이는 실제 API 재호출·현행 지역 검색·공급면적 비교의 검증을 뜻하지 않습니다. 기존 조회 도구의 정제 결함은 별도 수정·회귀검사가 필요하며, 추가 실호출 전에는 [API 안내](docs/api/README.md)의 조건을 확인합니다.

## 유지할 제품 규칙

- 공고 탐색에는 희망 시·군·구의 복수 선택과 예산을 필수로 받고, 공급면적 최소~최대(㎡·평)와 입주 시작월~종료월은 선택으로 둡니다. 입주는 공식 예정 기간과 겹침으로 판단하며 예산은 분양가+필수 옵션과 비교하고 세금·금융비용은 별도로 표시합니다.
- 초기에는 아파트 신규분양·무순위·잔여세대·재공급을 다룹니다. 접수 중 공고는 마감일순, 예정 공고는 시작일순으로 뒤에 표시하며 종료는 선택 포함합니다. 조건 충족 목록과 확인 필요 목록을 기본으로 구분합니다.
- 다른 탐색 조건을 충족하면서 예산 이내인 주택형·호실이 하나라도 확인되면 공고를 포함하고 해당 항목을 표시합니다. 여러 공고를 나란히 비교하는 기능은 후속으로 둡니다.
- 공식 PDF를 자동 확보하고 실패하면 사용자 업로드로 보완합니다. 핵심 값은 원문 대조·일관성 자동 점검을 통과한 경우 사용하며 출처·페이지를 표시하고 불명확한 값은 보류합니다.
- 기초 자금표·법령 근거 탐색과 대중교통·연결 도보·자동차 출퇴근 조회를 초기 포함합니다. 자동차 경로는 별도 연동 검증이 필요합니다. 자금표는 보유·날짜별 추가 자금을 확정·예상으로 구분해 납부액·부족분을 표시하며 설명은 실거주 첫 집 마련자를 우선합니다.
- 같은 동·읍·면에 후보가 1~4개이면 해당 후보만 제공합니다. 구·시·군에서 5개를 채우지 않습니다.
- 필요한 조회와 판별이 끝난 **정상 0개**일 때만 같은 구 또는 구 없는 시·군으로 확대합니다. 면적 미확인·주소 충돌·부분 수집·API 오류는 정상 0개가 아닙니다.
- 고유 주변 최대 5단지를 공급면적 ±5% 안에서 면적 차이순, 같으면 확인 좌표 간 직선거리순으로 선정합니다. 직접 지정은 현재 지역·비교 기준과 전체 5개 안의 교체로 지원합니다. 면적 범위 변경은 확인 후 적용하며 자체 거래는 별도 참고로 주변 수·0개 판정에서 제외합니다.
- 단지별로 가장 가까운 공급면적의 거래만 종류별 통계에 사용합니다. 유효 거래가 1건 이상이면 비교에 포함하며 1~2건은 적은 표본임을 표시합니다.
- 어느 거래 종류든 우선 지역에 확인된 주변 후보가 있으면 전체 보고서가 그 범위를 유지합니다. 다른 종류만 확대 지역에서 보충하지 않으며 종류별 가격·통계는 구분합니다.
- 거래 기간은 조회일까지 최근 1년으로 당월을 포함하고 사용자가 변경할 수 있습니다. 신고 지연·정정 가능성을 표시합니다. 공급면적 비교를 유지하며 면적 대응·복수 대응·윤일 경계·대표 좌표·동률 처리 등 세부 기준은 미정입니다.
- 선택한 주택형은 확인된 호실별 분양가+필수 옵션의 최소~최대 범위를 표시하며 특정 호실을 선택하면 그 가격으로 비교합니다. 일부 호실만 확인한 범위를 전체 가격 범위로 표시하지 않습니다.
- 매매·분양권·입주권을 구분하고 해제 거래를 제외합니다. 호가·리치고·수익모델은 범위에서 제외합니다.
- 첫 로그인 후 탐색·분석하며 기기 간 이어 사용합니다. 탐색 조건·목적지는 확인 후 공유하고 자금은 분석별 저장합니다. 사용자 입력은 삭제까지 보관하며 개별·계정 삭제를 지원합니다. 보고서 저장·다시 열기·PDF도 초기 범위입니다.

## 저장소 구성

```text
docs/prd/               제품 요구·제안·결정·수락 기준
docs/api/               API 설정, 데이터 대응표, 검증 요약·증거 색인
docs/development.md     개발 순서와 실행 안내
docs/development-plan.md 기초 개발 우선 전체 계획과 검수 이정표
docs/infrastructure.md DB·환경·배포·검증 상태
docs/frontend-handoff.md 화면 팀의 인증·데이터 연결 계약
api/, src/server/       Vercel 진입점과 공통 인증 조회 API
src/db/                 Supabase 생성 타입
dev/                    같은 API의 로컬 실행기
supabase/               DB 마이그레이션·로컬 설정·수동 원격 검사
tests/backend/, tests/database/ API·DB의 합성 경계 검사
scripts/                조회·수집·PDF·역사적 검증 도구와 경계 테스트
tests/fixtures/         실제 응답을 포함하지 않는 합성 자료
.github/workflows/      인증값 없이 실행하는 자동 검사
.env.example            빈 인증값 템플릿
```

API 키, 개인 계정 기록, API 응답 원문, PDF/HWP 원본, 뉴스 본문·발췌와 교통 경로 데이터, 과거 발표 자료는 업로드하지 않습니다. 공개한 검증 수치와 원 프로젝트의 로컬 증거 위치는 [증거 색인](docs/api/evidence-index.json)으로 추적합니다. 데이터 배포 범위와 제3자 이용 조건은 [데이터 관리 안내](docs/data-handling.md)를 확인합니다.

**개발 시작점:** [전체 개발 계획](docs/development-plan.md)에 따라 API 계약·응답 정제·공고/거래 정규화부터 시작하고 DB 저장·영속 작업·비교 결과 조회를 연결합니다. 공급면적·권리·지역·PDF의 실자료 검증을 병행하며, 화면 팀에는 동작 계약과 합성 응답을 먼저 제공합니다. 첫 종단 흐름의 검증과 전체 제품의 출시 수락은 구분합니다.
